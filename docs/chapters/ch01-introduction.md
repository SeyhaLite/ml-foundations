## គោលបំណងនៃជំពូក

បន្ទាប់ពីអានជំពូកនេះ អ្នកនឹងអាច៖

- ពន្យល់បានថា **LLM** (Large Language Model) ដំណើរការយ៉ាងដូចម្តេច
- ស្គាល់ **ត្រកូលម៉ូដែល Qwen** ពីជំនាន់ Qwen3 ដល់ Qwen3.8
- ប្រាប់បានថា **fine-tuning** ខុសពី prompting និង RAG ត្រង់ណា និងពេលណាគួរប្រើវា
- យល់ពី **ផែនទីផ្លូវ** (roadmap) នៃសៀវភៅ និងលក្ខខណ្ឌត្រៀម

## តម្រូវការមុន (Prerequisites)

| ជំនាញ | កម្រិតត្រូវការ |
|---|---|
| Python | មូលដ្ឋាន — function, dict, list, pip install |
| Terminal/Command line | cd, ls, activate venv |
| គណិតវិទ្យា | មិនចាំបាច់កម្រិតខ្ពស់ — យើងពន្យល់ជាភាសាសាមញ្ញ |
| ភាសាអង់គ្លេសបច្ចេកទេស | អានឯកសារ API បានខ្លះៗ (ឯកសារផ្លូវការមិនទាន់មានជាខ្មែរ) |
| Hardware | GPU យ៉ាងតិច ១០–១៦ GB VRAM **ឬ** Google Colab (ជំពូក ២) |

## LLM គឺជាអ្វី?

**Large Language Model** គឺជាបណ្តាញណឺរ៉ូន (neural network) ដ៏ធំ ដែលរៀនពីអត្ថបទ
រាប់ពាន់ពាន់លាន token ដើម្បីធ្វើកិច្ចការតែមួយគត់៖ **ទស្សន៍ទាយ token បន្ទាប់**។

ឧទាហរណ៍ បើយើងបញ្ចូល «រាជធានីរបស់កម្ពុជាគឺ» ម៉ូដែលនឹងទស្សន៍ទាយពាក្យ «ភ្នំពេញ»
ដោយផ្អែកលើស្ថិតិដែលវាបានរៀន។ ការឆ្លើយសំណួរ ការបកប្រែ ការសរសេរកូដ — ទាំងអស់នេះ
គឺជាការទស្សន៍ទាយ token ម្តងមួយៗបន្តគ្នា។

ដំណើរការបង្កើត LLM មានពីរដំណាក់កាលធំៗ៖

1. **Pre-training** — រៀនភាសា និងចំណេះដឹងទូទៅពីទិន្នន័យដ៏ច្រើនមហាសាល
   (ត្រូវការ GPU រាប់រយគ្រឿង រាប់ខែ — ក្រុមហ៊ុនធំៗធ្វើ)
2. **Post-training / Fine-tuning** — រៀន «របៀបនិយាយជាមួយមនុស្ស» និងជំនាញជាក់លាក់
   ពីទិន្នន័យតូចជាង (រាប់រយ ឬរាប់ម៉ឺនឧទាហរណ៍ — **យើងអាចធ្វើបាន!**)

## ត្រកូល Qwen — ពី Qwen3 ដល់ Qwen3.8

**Qwen** (通义千问 — «សំណួរពាន់ចម្លើយ») គឺជាត្រកូល LLM កូដចំហរបស់ក្រុមហ៊ុន Alibaba។
ខាងក្រោមជាជំនាន់សំខាន់ៗដែលសៀវភៅនេះគ្របដណ្តប់៖

### Qwen3 (មេសា ២០២៥)

- ម៉ូដែល dense ពី **0.6B** ដល់ **32B** ប៉ារ៉ាម៉ែត្រ និង MoE ដល់ **235B-A22B**
- នាំមុខគេលើពិភពលោកក្នុងការបើក/បិទ **hybrid thinking mode**
  (`enable_thinking=True/False`) — អាច «គិត» មុនឆ្លើយ ឬឆ្លើយភ្លាមៗ
- កំណែធ្វើឱ្យប្រសើរ **2507** (កក្កដា ២០២៥)៖ បំបែកជា `-Instruct-2507`
  (មិនគិត — លឿន) និង `-Thinking-2507` (គិត — ស៊ីជម្រៅ) ជាមួយ context 256k
- ដំណើរការលើ `transformers>=4.51`

### Qwen3.5 (១៦ កុម្ភៈ ២០២៦)

ជំនាន់ដែលផ្លាស់ប្តូរច្រើនបំផុត៖

- **Multimodal ពីកំណើត** — checkpoint តែមួយមានទាំងភាសា និង vision encoder
  (architecture `Qwen3_5ForConditionalGeneration`)
- **Hybrid architecture ៣:១** — ស្រទាប់ Gated DeltaNet (linear attention) ៣ ឆ្លាស់នឹង
  Gated Attention (full attention) ១ → context វែង **262,144 token** ដោយចំណាយតិច
- ទំហំ៖ **0.8B, 2B, 4B, 9B, 27B** (dense) និង **35B-A3B, 122B-A10B, 397B-A17B** (MoE)
- ភាសា **២០១** រួមទាំងភាសាខ្មែរ
- ⚠️ ត្រូវការ **transformers v5** (`>=5.2`) — v4 មិនស្គាល់ `model_type: qwen3_5` ទេ

### Qwen3.6 (២០២៦) និង Qwen3.8 (សីហា ២០២៦)

- **Qwen3.6** — កំណែកែលម្អស្ថិរភាព និង agentic coding (27B, 35B-A3B)។
  ប្រើ architecture ដដែល `qwen3_5` ជាមួយ Qwen3.5។
- **Qwen3.8** — ការចេញផ្សាយម៉ូដែលថ្នាក់ Qwen-Max ជាកូដចំហ (27B, 2.4T-A95B, Flash-Next)
  បន្ថែម `reasoning_effort` និង `preserve_thinking`។ ត្រូវការ **transformers ≥ 5.8**។

តារាងលម្អិតសូមមើល {doc}`តារាង Compatibility </compatibility>`។

## ហេតុអ្វី Fine-Tuning? ប្រៀបធៀបជាមួយ Prompting និង RAG

| វិធីសាស្ត្រ | គំនិត | ពេលណាគួរប្រើ | ចំណាយ |
|---|---|---|---|
| **Prompting** | សួរម៉ូដែលដើមមិនប្រែប្រួល | កិច្ចការទូទៅ សាកល្បងលឿន | ស្ទប់តែថ្លៃ API |
| **RAG** | ភ្ជាប់ឯកសារខាងក្រៅទៅ prompt | ចំណេះដឹងដែលប្រែប្រួលញឹកញាប់ | មធ្យម (vector DB) |
| **Fine-tuning** | ហ្វឹកម៉ូដែលលើឧទាហរណ៍ជំនាញ | **រៀនរចនាបថ/ទម្រង់ថ្មី** ឆ្លើយខ្មែរស្ទាត់ កាត់បន្ថយ prompt វែងៗ | ដំបូងខ្ពស់ បន្ទាប់ថោក |

ចំណាំសំខាន់៖ fine-tuning ពូកែខាងបង្រៀន **របៀប** (ទម្រង់ រចនាបថ ភាសា) ជាង
បញ្ចូល **ចំណេះដឹងថ្មី**។ បើត្រូវការចំណេះដឹងដែលប្រែប្រួល — ប្រើ RAG។

## ហេតុអ្វី LoRA?

ការហ្វឹកម៉ូដែល 4B ពេញលេញ (full fine-tuning) ត្រូវការ VRAM ~៤ ដងនៃទំហំម៉ូដែល
(ទម្ងន់ + gradient + optimizer states)។ **LoRA** (Low-Rank Adaptation) ដោះស្រាយបញ្ហានេះ
ដោយបង្កកទម្ងន់ដើមទាំងអស់ ហើយហ្វឹកតែម៉ាទ្រីសតូចៗបន្ថែម (~០.១–១% នៃប៉ារ៉ាម៉ែត្រ)។
លទ្ធផល៖ Qwen3.5-4B អាចហ្វឹកក្នុង VRAM ~១០ GB ជំនួស ~៦០ GB។ ជំពូក ៥ នឹងពន្យល់លម្អិត។

## ផែនទីផ្លូវនៃសៀវភៅ

```text
ជំពូក ២  ដំឡើងបរិស្ថាន          → ម៉ាស៊ីនអ្នករួចរាល់
ជំពូក ៣  ម៉ូដែល + tokenizer       → ផ្ទុក Qwen និងសន្ទនាដំបូង
ជំពូក ៤  ទិន្នន័យ                  → dataset ខ្មែរត្រឹមត្រូវ
ជំពូក ៥  LoRA                     → យល់អ្វីដែលយើងនឹងហ្វឹក
ជំពូក ៦  ហ្វឹក SFT                 → ការហ្វឹកពិតប្រាកដ
ជំពូក ៧  វាយតម្លៃ + inference     → ដឹងថាវាល្អឬអត់
ជំពូក ៨  save/merge/deploy         → យកទៅប្រើជាក់ស្តែង
ជំពូក ៩  កម្រិតខ្ពស់               → QLoRA, MoE, DPO, multimodal
ជំពូក ១០  troubleshooting          → នៅពេលមានបញ្ហា
```

## សង្ខេប

- LLM ទស្សន៍ទាយ token បន្ទាប់ — fine-tuning គឺការរៀនបន្ថែមពីឧទាហរណ៍ជំនាញ
- Qwen មាន ៤ ជំនាន់សំខាន់ក្នុងសៀវភៅនេះ៖ Qwen3, Qwen3.5, Qwen3.6, Qwen3.8
- Qwen3.5+ ត្រូវការ transformers **v5** — កុំភ្លេចចំណុចនេះ!
- LoRA ធ្វើឱ្យការហ្វឹកម៉ូដែលធំអាចធ្វើបានលើ GPU តែមួយ

## លំហាត់

1. ចូរពន្យល់ជាភាសាខ្មែរ (៣–៤ ប្រយោគ) ថាហេតុអ្វីបានជា RAG សាកសមជាង
   fine-tuning សម្រាប់ «តម្លៃម្ហូបអាហារដែលប្រែប្រួលរាល់ថ្ងៃ»។
2. ស្វែងរក model card នៃ `Qwen/Qwen3.5-4B` លើ Hugging Face ហើយកត់ត្រា៖
   ចំនួនស្រទាប់ (layers), context length និង license។
3. គិតមើល៖ កម្មវិធីអ្វីមួយដែល **អ្នក** ចង់បង្កើតដោយ fine-tune ម៉ូដែលខ្មែរ?
   សរសេរឧទាហរណ៍សំណួរ-ចម្លើយ ៥ គូដំបូង។
